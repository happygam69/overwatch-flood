## The single most useful result of this pass: the name pages are already decoded

`scripts/strlookup.py` (new, 55 lines) resolves any `.data` address against
`../../strpool.txt` (56,835 address→text rows). **The pool's address for a XOR-8 name page
is the page base + 8** — i.e. the *length word*, not the payload:

| page field | address | example (`0x14384d730`) |
|---|---|---|
| key[8] | base + 0 | `0x14384d730` |
| length word `len & 0xffffff`, tag byte `base+0xb` | base + 8 | `0x14384d738` = pool ★ |
| payload (XOR key[i&7]) | base + 0xc | `0x14384d73c` |

So the pool decodes the pages that the decompiler shows as `DAT_1438…`, and open thread 1
("decrypt a settings name") is answered for *naming* purposes without the binary — the
XOR-8 pages sampled in this pass all resolve to readable strings. Two proofs from the text:

- `FUN_1405b7b40` (chunk `0267`) XOR-loops `&DAT_14384d73c` against `0x14384d730`, guarded
  by byte `DAT_14384d73b`, length `_DAT_14384d738 & 0xffffff`; the two branches log
  `DAT_14384d714` / `DAT_14384d73c` = pool's **"Serialization didn't work!"** /
  **"Serialization worked!"** at `0x14384d710` / `0x14384d730` (base+8 each time).
- `FUN_1405ddb40` (chunk `0273`) decrypts **13 consecutive pages** `0x14384dad0…0x14384dc80`
  and returns `local_78[i]` for `i ≤ 0xc`, else the page at `0x14384dc8c`. Pool:
  `UserRequest, QueuePopped, QueueNotReserved, InvalidRulesetGUID, ServerError,
  ServerDraining, ReadyCheckTimeout, PartyNotFound,
  PartyAlreadyExistsInDifferentQueue, PartyFailedToJoinMatch, RulesetGUIDNotEnabled,
  CrossPlayChanged, MatchInputPoolChanged`, else `Invalid`. **That is the match-queue
  error enum 0–12 → name** (evidence; the mapping is the array order in the code).

`scripts/strscan.py` (new, 40 lines) applies the same lookup to every `14xxxxxxx` literal in
a chunk, which is how the zone labels below were obtained.

## What this range is

**Meta-game client, not the registry machine and not the HUD.** No `cd360`, no `d4f30`/
`d4f70`/`d4fb0`, no `c2d50`/`c2d70`/`c7880`, no `atexit`. What is here, in order:

1. `0x1405b3080`–`0x1405bb220` — **staged scene-object spawn queue** (7 payload kinds,
   0x90/0x130/0xba/0x480/0x5d0/0x980-stride rows, 600-tick expiry, ≤8 pending, ≤100
   retries) plus its grid/tracked-entity tables [inference: the receive side of an
   entity-replication path].
2. `0x1405bb220`–`0x1405c5480` — **spatial instancing**: AABB tree walk (`movmskps`),
   voxel grid, sorted-by-`+0x5c` priority list, parallel per-record update, distance/
   frustum culling with hysteresis, cluster merging, orient-to-surface-normal. 0x110-B
   records, 3 pools of 0xd0-B slot objects, dirty-bitmask propagation.
3. `0x1405c5cd0`–`0x1405cfa00` — engine miscellany: dirty-bit set/clear API, ray/sphere
   averaging, triangle-normal extraction, a 0x40-stride ring-bucket map, tagged-pointer
   validation, scene property setters (`FUN_1407e6350/69d0/6290/6240`).
4. `0x1405cfa60`–`0x1405e1de0` — **social / presence / profile**: per-player attribute
   containers keyed `{bnet_dbid, title_id, group, field, unique_id}`, presence publish
   with length limits, voice-report event, a 20-thread job pool that zlib/decrypts blobs,
   Steam stats/user-stats sync, HTTP upload, `SteamUtils010`.
5. `0x1405e1680`–`0x14060c340` — **input**: XInput gamepad state/slot arrays, stick radial
   deadzone + circular clamp, rumble envelopes with keyframe interpolation, device-change
   callbacks, console-variable registration for `input.*`, a 14-column debug table.
6. `0x14060c6b0`–`0x140610980` — **JSON parser + JSON object model** (see below) and the
   C++ container teardowns for it.

### 9. `0x14060c6b0`–`0x140610980` (56 fns) — JSON parser + object model

The **JSON implementation** is the most reusable finding of the last zone:

- Value descriptor = **0x10 bytes**, data in `+0x0`, tag in the `u16` at `+0xe`.
  Tags observed: `3` = object, `4` = array, `9`/`0xa` = true/false (`FUN_140610920`,
  `tag = kind + 9`), `0x96/0xb6/0x116/0x196/0x1d6/0x1f6` = integer sub-kinds (sign × width:
  offsets `0x20` = "signed", `0x40` = "32-bit", `0x100` = "wide"), `0xc05` = heap string
  (length in the tag's low bits, pointer at `+0x8`), `0x1c05` = **inline string** with
  length `0xd - lowbyte` (`FUN_14060fc90`).
- `FUN_14060ebb0` (6.7 KB) = value dispatch on the first byte
  (`"`→`FUN_14060e880`, `[`→`FUN_14060dee0`, `{`→object loop, `t`/`f`/`n`→literal walker,
  default→`FUN_14060e0e0` number). Error codes written to `+0x30` and byte offset to
  `+0x38`: `3` bad literal, `4` expected quote, `5` expected colon, `6` expected `,`/`}`,
  `7` unexpected end in array, `8` bad `\u`, `9` bad surrogate, `0xa` bad escape,
  `0xb` unexpected end in string, `0xc` control char in string, `0xd` number too large,
  `0xe` empty fraction, `0xf` bad exponent, `0x10` trailing garbage.
- `FUN_14060e880` = string with `\uXXXX` + **surrogate-pair** handling
  (`(hi-0xd800)*0x400 | (lo-0xdc00)) + 0x10000`) and UTF-8 encoding via
  `FUN_14060da00` (1/2/3/4-byte forms, `0xf0` lead for ≥0x10000).
- `FUN_14060db90`/`FUN_14060dc50` = exponential string-buffer grow (`malloc`→`realloc` at
  `+0x10/+0x18/+0x20/+0x28/+0x30`).
- `FUN_14060f040` = **SSE2 whitespace skip**: compares 16 bytes at a time against four
  16-byte tables (`DAT_142f85d90/d a0/d b0/d c0`), ORs the masks and takes the first
  zero lane — hand-vectorised `strspn(" \t\r\n")`.
- `FUN_14060f590` = `unordered_map<std::string, json>` insert: 0x38-B nodes
  (`+0x1` string, `+0x30` value), `FUN_142693a50` hash, chaining at `+0x8`, load-factor
  `*(f32*)(h+3)` triggers `FUN_14061ba80(cap*2)`.
- `FUN_14060f150`/`f230`/`f3a0`/`f3f0`/`f480`/`f4d0`/`f520`/`fa50`/`fba0`/`fc90`/`fd30`/
  `10040`/`10160`/`10220`/`103b0`/`10420`/`104e0`/`10550`/`105c0`/`10650`: the
  destructors/growers for every row shape the JSON document owns — 0x20, 0x88, 0xa0, 0xc0,
