## What this range is

**The client's receive side for the match lifecycle.** No registrar machinery. Ten zones:

1. `0x140610c60`–`0x140614290` — LobbySystem handlers, dispatch block `0x5014`–`0x5021`.
2. `0x140614b90`–`0x14061a780` — instance-info / join / leaver handlers (`0x5078`–`0x507e`,
   `0x5140` block), saved "recent matches" JSON glue.
3. `0x14061a840`–`0x14061e8e0` — world/instance state handlers, account family, hotfix
   pipeline tail.
4. `0x14061ec00`–`0x140623900` — **bitstream deserializer core** (read-bit-field
   `FUN_1406232f0`, entity header `FUN_140622f00`, entity field `FUN_140623120`,
   hash-map families C/E, the 67 KB `FUN_140623900` entity-update dispatcher).
5. `0x1406251a0`–`0x14062a880` — **entity delta apply** (baseline/diff component compare,
   bit writer `FUN_1406264c0`, heapsort/introsort over 0xc0-B records, match-phase handlers
   `0x53000`/`0xcf09`–`0xcf25`).
6. `0x14062a980`–`0x14062e410` — match-phase + replay/record-set plumbing, obfuscated
   equity/restore walkers.
7. `0x14062ed40`–`0x140631b60` — saved-match list sort/merge, projectile & impact effect
   trackers.
8. `0x140631ee0`–`0x140637450` — **JSON writer** (value serializer + decimal formatters) and
   the `NarrativeViewerContent` schema writers.
9. `0x140637aa0`–`0x14063dd00` — **JamMessage dispatch tables** (~50 dispatchers mapping
   contiguous message-id blocks to the handlers of zones 1–8).
10. `0x14063ddf0`–`0x1406446c0` — **gameplay event-bus subscription layer** (~30 identical
    registrars over the `0xb0` descriptor + `0x30` listener idiom).

Evidence for the whole layout: the dispatch tables in zone 9 map message ids **exactly** to
the zone-1/2/5 handler functions (e.g. `0x5078→FUN_140614290`, `0x5014→FUN_140612ed0`,
`0x5140→FUN_140616b30`, `53000→FUN_140627dd0`, `0xcf0f→FUN_140628730`), so this file
territory is one subsystem, not a grab-bag.
