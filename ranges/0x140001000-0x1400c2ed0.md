# Pass 1 — `.text` `0x140001000` – `0x1400c2ed0`

Record for the ledger's "pass 1 (pre-protocol)" row, which had no record file until now.
Chunks `0000`–`0008` (`work/flood/chunk_0000.txt` … `chunk_0008.txt`) were read line-by-line;
`chunk_0009`–`0013` were **not** read — see the read-state table at the end.

Summary: this pass is entirely **library preamble** — a hand-optimised DEFLATE inflate, the
NVAPI stub layer, an NVIDIA driver-redirection `LoadLibrary` shim built on D3DKMT/SetupAPI/
registry, and ~2,000 CRT/C++ static initialisers (five templates). No gameplay, no asset,
no protocol code lives in `0x140001000`–`0x1400c2ed0`.

Evidence for the codec family: RFC1951 shapes (`0x7ff`/11-bit litlen table, 15-bit distance,
`extra = len>>0x10`, "bit length in low byte of table entry") plus 64-bit MSB-aligned bit
buffers. **Inference:** this is ISA-L/igzip-derived stateless inflate code (8-byte
litlen+dist pair entries, `vpinsrb` in the fast path) rather than stock zlib. Cheap check to
confirm: 8-byte entry with `extra` at +4 is `struct hufftbl` in igzip; stock zlib uses
`code`/`op`/`bits` in a 16-bit word only. Not resolved here.

- `0x140037670` — 135 B, **48 callers**: `NvAPI_Initialize` guard used by every wrapper below.

## Data-obfuscation convention (found ~60×, stable layout)

```
+X+0x00 : 8-byte XOR key           (e.g. DAT_143865fB0)
+X+0x08 : uint32, low 24 bits = length, high byte unused
+X+0x0b : flag byte; if non-zero, decrypt and then clear length to (len & 0xffffff)
+X+0x0c : ciphertext, XOR'd byte-wise with key[i & 7]
```
Every instance is guarded by its own flag, so the transform is idempotent and re-entrant-safe
by construction. 40-byte (0x28) payloads are the common case; 2–4 blocks per function occur.
**Inference:** these are build-time-obfuscated strings/keys; the 0x28 length matches SHA-1.
