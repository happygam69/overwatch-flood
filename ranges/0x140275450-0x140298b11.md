## Reading conclusion (what this range is for)

Pass 14 is the densest stretch of the **generated type/object registry** yet: seven registration
blocks (287 types) interleaved with builder seas that instantiate them, `id→name` records that
cross-link registrations, 2-entry lookup tables built from decrypted names, and a shutdown/atexit
table whose row shapes keep multiplying. Three structural facts are new at this depth:

1. **The static-root era is over.** Classes are no longer rooted on fixed vtable descriptors —
   every object roots on a registration output of the same block, i.e. the registry is now
   self-bootstrapping: registrations produce class objects, later functions use those class
   objects as bases. [inference: the earlier static roots were the first generation; from here on
   the code builds descriptors at runtime.]
2. **The registry writes into the CompilerIDFilter chain.** The 244-B wrapper rooted on a
   CompilerIDFilter payload storing `&PTR_s_CompilerIDFilter_1438d9ff0` ties the anonymous
   XOR-named registry to the one named subsystem in the file. [inference: what is being
   registered here is, at least in part, the shader/compiler filter machinery.]
3. **Names are heavily shared; ids are not.** 287 registrations carry 287 distinct hashes, while
   builders reuse 61 names across 90 decrypts, and four ids now map to one hash — the registry is
   one-name-many-instances plus an id alias table.

No gameplay, network, asset or readable-string code appears; this is still startup-time
registration, now demonstrably feeding a named subsystem.
